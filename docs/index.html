env-vault

Secure .env file manager with encryption and version control integration.

Overview Install Quick Start Commands Configuration GitHub

Overview

env-vault is a command-line tool that encrypts .env files and stores them outside Git, linked to a repository. It uses Argon2id key derivation and AES-256-GCM for strong encryption, with HMAC integrity verification on every secret.

Features

  • Strong Encryption: Argon2id + AES-256-GCM
  • Integrity Verification: verify command checks HMAC on all secrets
  • Secret Providers: Bitwarden Secrets Manager, OS keyring, or interactive prompt
  • Git Integration: Auto-detects repository context (user/repo)
  • Cloud Sync: Optional Google Firestore backend
  • Cross-Platform: Windows, macOS, Linux
  • Secure Storage: Local vault with file locking and audit logs

Installation

Homebrew (macOS / Linux)

brew tap bulga138/env-vault
brew install --cask env-vault
env-vault version  # → env-vault version 1.0.0

Pre-compiled binaries

Download the latest release from the GitHub Releases page.

From source

git clone https://github.com/bulga138/env-vault.git
cd env-vault
go build .
# or
go install .

Requires Go 1.24+.

Quick Start

1. Bitwarden Configuration (Recommended)

export BWS_PROJECT_ID="your_bitwarden_project_id"
bws login

2. Save a Secret

cd /path/to/your/project
env-vault save --use-bitwarden

If a key for this repo doesn't exist, a new one is generated and you're prompted to save it in Bitwarden.

3. Retrieve on a New Machine

cd /path/to/your/project
env-vault get --use-bitwarden

If an existing .env is found, it's saved as .env.recovered.

Commands

CommandDescription
saveEncrypts and stores the .env file for the current repository.
getRetrieves and decrypts the .env file.
rotate-passRotates the master password (useful for updating the Bitwarden key).
generate-passGenerates a new secure 16-character master password.
verifyVerifies HMAC integrity of all secrets in vault.json.
sync-saveUploads the encrypted secret to Firestore.
sync-loadDownloads all secrets from Firestore into the local vault.
usersManage vault users (list, add, remove).
aclManage per-repo access control (grant, revoke, list).
auditView audit logs (list, tail) with optional filters.
keyringManage OS keyring entries (set, get, delete, status).
mnemonicGenerate or recover a BIP39 recovery phrase.
backupCreate a rotated backup of the vault (keeps 10 most recent).
restoreRestore a vault backup (confirms overwrite unless --force).
p2p / peer / relayPeer-to-peer sync via relay/rendezvous.
versionPrint version and exit.

Global Options

OptionDescription
--use-bitwardenUse Bitwarden to fetch the master password.

--repoSpecify repository name (e.g. user/repo).
--sync-strategyConflict resolution for sync-load: newest, remote, local, skip.

Security

  • Master passwords are never stored on disk. They are securely cleared from memory immediately after use.
  • HMAC Verification: Each secret has an HMAC verified with the master key to detect tampering.
  • The vault.json file uses restricted permissions (0600) and file locking during writing.
  • Each entry uses a unique salt for Argon2id key derivation.
